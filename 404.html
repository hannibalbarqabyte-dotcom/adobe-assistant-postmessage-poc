Security research PoC — ADOBE-OG0PVWYY

This page is hosted at , an origin explicitly listed in the Acrobat AI Assistant iframe's CSP frame-ancestors allowlist. It demonstrates that the assistant's postMessage listener accepts cross-origin messages with no event.origin check, including the adbmsgui_UPDATE_ACCESS_TOKEN handler that sets the assistant's auth token.

Authorized testing only — own Adobe test accounts.

Direct iframe — allowed by CSP frame-ancestors

Frames the assistant directly from this hosted origin (*.aem.page / *.hlx.page are explicitly listed in the assistant's CSP frame-ancestors, unlike an arbitrary attacker.com). No popup, no window.open — just an <iframe> on this page, served by this real hosted site.


Step 1 — reach the victim's live session (popup)

Opens acrobat.adobe.com in a new window from this page. If this page is visited in a browser that is already logged into Acrobat (e.g. via a phishing link while the victim has Acrobat open), the new window automatically carries that session's cookies.

Step 2 — sanity check (benign)

Broadcasts adbmsgui_UPDATE_UI_THEME to every subframe of the popup. If the assistant's background flips light/dark, the listener accepted a message from this non-Adobe origin with no origin check.

Step 3 — cross-account token injection (the impact)

Paste an authorized test account's valid Adobe access token (own accounts only — never a third party's), then broadcast. This reaches the popup's assistant iframe and overwrites its accessToken; the assistant then authenticates POST assistant.adobe.io/api/v2/session with the injected token, binding the victim's live assistant session to whichever account the token belongs to.
